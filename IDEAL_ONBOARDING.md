# Magnific Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: контент-дизайнер/маркетолог или разработчик, который уже платит за Magnific (бывший Freepik API) напрямую и хочет управлять генерацией изображений/видео/аудио из чата, вместо того чтобы держать открытой отдельную вкладку magnific.com.

## 1. Credential type
Один статический API key (`x-magnific-api-key`, server-to-server), никакого OAuth — Magnific поддерживает только приватные ключи для server-to-server вызовов (подтверждено `docs.magnific.com/authentication`).

## 2. Идеальный флоу
1. **Первое открытие** — `Empty`-состояние: "Подключите свой Magnific API-ключ, чтобы генерировать изображения, видео и аудио прямо здесь" + прямая ссылка "magnific.com/user/organization/api-keys" (Support-ссылка из документации).
2. **Форма** — одно поле `api_key` (password-type, лейбл "API-ключ Magnific", placeholder — пример формата ключа, не generic "введите ключ").
3. **После успеха (`connect_magnific`)** — сразу видно баланс credits команды (Analytics `team-credit-usage`) + список последних задач генерации (`list_generation_results`), без дополнительного клика. Момент истины: "у меня осталось X credits, вот что я генерировала недавно" — знакомая картина для тех, кто уже пользовался magnific.com.
4. **Media Studio cross-app awareness** — идеально: если Media Studio уже использует Magnific как provider у этого же пользователя (общий аккаунт), явная подсказка не нужна технически (разные API-ключи разных приложений могут отличаться), но полезно упомянуть в Empty-состоянии: "Это отдельное приложение — независимое от Media Studio, у него свой собственный API-ключ".
5. **Ошибка "insufficient credits"** — Magnific прерывает генерацию, если баланс credits закончился на середине — конкретное сообщение с текущим балансом и ссылкой на пополнение, а не общий "request failed".
6. **Долгие видео-задачи** — некоторые video-модели (Kling, WAN и т.п.) могут занимать несколько минут. Идеально: прогресс-индикатор с оценкой оставшегося времени (Magnific API этого не даёт явно — реалистично только "Обрабатывается, это может занять несколько минут" + периодический авто-поллинг).
